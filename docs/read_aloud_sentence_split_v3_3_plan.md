# 英文朗读分句 V3.3 实施计划

状态：代码、端侧模型与跨平台本地验收已完成；阿里与火山各有一个文本模型通过受约束
路径选择门槛。文章级版本继续使用 `read_aloud_dp_v3` / `reviewed_dp_v3`；内部求解器为
`syntax_solver_v3_3`。

## 基线与目标

- 退役 V2 在 243 项固定金标中精确匹配 112 项（46.09%）。
- V3.2 官方 UDPipe 对照模型精确匹配 199 项（81.89%），人工认可路径进入候选集
  208 项（85.60%）。
- 首轮十类通用输入候选覆盖：官方对照模型 7/10，项目 EWT 模型 6/10；截至计划
  冻结时远程调用为 0，费用为 0 元。
- V3.3 的首要门槛是候选召回而不是本地排序：243 项固定金标和十类通用输入的
  人工认可路径都必须进入候选集，才允许调用收费 AI。

## 实施约束

1. 原文正字句界、正文完整回拼、30 词输出上限、20 词最长无标点跨度和只切分
   不合并继续作为硬约束；安全原句保持不动。
2. 优先求解 `; : — –` 和句法明确确认的从句逗号。存在合格纯标点路径时直接
   采用，不允许无标点路径竞争，也不调用 AI。
3. 纯标点无解时建立完整安全词间候选格。只有字符/token 内部、多词 token 内部、
   数字/小数/缩写内部、clitic 和 offset 异常等原文级原子结构可以硬禁止。
4. 依存关系、跨越弧、子树完整性、主谓与从句结构只提供风险证据，不能删除安全
   候选；禁止恢复 V2 词表，禁止为书名、角色、单词或固定坏例增加生产例外。
5. 通用协议第一轮最多返回 8 条路径；扩展轮最多返回 24 条路径，由最低风险、边界集合差异
   和安全边界覆盖三组组成。已验收的 DeepSeek V4 Flash 配置首轮直接使用最多 24 条精简扩展
   候选，避免解析器风险元数据干扰语言判断。长度均衡始终是最后一个评分因素。
6. AI 只能返回程序提供的 `candidatePathId` 或保留值 `REJECT`。每篇文章最多两次
   远程分句请求：阿里先使用初轮候选，合法拒绝后使用扩展候选；DeepSeek 首轮使用精简扩展
   候选。非法响应、拒绝或超时最多重试一次，仍失败时使用最低风险本地路径并显式记录 emergency。
7. 缓存键包含求解器、候选轮次、候选集合哈希、提示词版本、解析器/模型 SHA、AI
   厂家和模型。失败、mock、非法响应和 `REJECT` 不写成功缓存。
8. 分句冻结后才翻译；旧文章、旧翻译、TTS、图片、字幕和视频在通用门槛通过前均
   不迁移或重建。

## 解析器策略

- 本轮不继续训练新的通用依存模型。先完成多词 token 的精确 offset 映射验证。
- UDPipe 是生产端结构证据来源；官方 UDPipe、Stanza 和 spaCy 仅作开发期独立参考，
  不投票、不进入 App。
- 项目 EWT 模型只有在原生桥、独立 EWT 指标、候选召回和 Windows/Android 一致性
  全部通过后才固定 SHA。UAS/LAS 只是健康度旁证，不代替分句任务指标。

## 接口、审计与缓存

- 每个安全词间间隙记录原文位置、边界类型、句法证据、风险向量和硬阻断原因。
- 每个原句记录初轮与扩展轮候选、稳定路径 ID、候选集合哈希、AI 决定、扩展原因、
  最终轮次、远程尝试、token 和估算费用。
- `article_segmentation_runs.candidate_paths_json` 使用带 schemaVersion 的对象保存完整
  候选与选择轨迹；已有列继续保存最终路径和费用，不给文章业务表增加临时字段。
- AI 提示词和响应保持固定 JSON 协议，绝不接受自由 token 位置、改写正文或翻译。

## 验收门槛

- 243/243 固定金标存在至少一条 approved path；十类通用输入达到 10/10。
- 冻结至少 60 个不参与规则调优的多文体保留案例，报告候选覆盖和最终选择结果。
- 固定禁止 `dust | in`、`throat | and`、`to | the gravelled carriage-drive`、
  `as they | peeped`、`could only | feel`，但这些字符串只能存在于测试数据。
- 纯标点路径存在时不调用 AI；错误依存树不能删除安全路径；`REJECT` 只扩展一次；
  每篇文章远程分句请求不超过两次；扩展轮成功缓存可以直接复用。
- 所有输出完整回拼、不丢词重词、不跨正字句、每段不超过 30 词、无标点跨度不
  超过 20 词；解析器失败必须留下可查询 emergency。
- 两家文本供应商分别重复三次，协议合法率、approved path 命中率和重复一致性均为
  100%，累计调优费用不超过 50 元。
- Flutter、Web、NLP、数据库、历史回归、Windows Release 和 Android 构建全部通过，
  Windows/Android 使用同一模型 SHA 和 fixtures。
- 最后只读运行柳林风声 E01–E62，逐项审核全部无标点切点、短碎片、超过 16 词跨度、
  emergency 和版本差异；通过前不写数据库、不生成 TTS/视频、不访问网盘。

## 明确反例

“遇到一个坏例子就增加一个词、角色名或固定短语”是禁止方案。任何修复必须来自通用
原文边界、token offset、候选完整性、依存证据或确定性求解规则，并在未参与调优的多文体
保留集上验证。

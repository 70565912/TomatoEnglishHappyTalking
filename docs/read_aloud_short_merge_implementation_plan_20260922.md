## 1. 最新要求与唯一处理链路

用户已明确：

- 不足4词不能作为新算法的最终分句保留。
- 合并后的上限按原分句规则分层处理：合适范围、逐步加强的分句范围、强制分句范围、最后硬上限。
- **先合并，再做分句，不做多次分句。**
- 质量、速度、代码量必须按工程规则共同优化，不能只追求切分结果正确。

采用唯一流程：

```text
原文和既有parser文档
  → 整理原始求解单元：不足4词的单元先与邻接内容合并
  → 每个最终求解单元一次事实构建、一次有界DAG
  → 从同一DAG生成满足最小词数与原分层规则的候选
  → 本地/AI选择合法路径
  → 一次校验、保存最终结果
```

合并发生在首次DAG求解前，只整理输入单元；它不产生最终句槽。合并后的待求解单元可以超过30词，交由同一次求解切分；**30词硬上限针对最终输出块及DAG分段边**，不能用它阻止31词或更长原文进入求解器。

分句阶段把最终最小词数纳入边的合法性，避免同一单元又切出不足4词。因此不需要“先切→后并→重切”、后置借词修复、失败窗口重跑、singleton产物冻结或第二套规范化结果。

用户当前目标明确为“4词以下”：处理1–3词，最终至少4词；恰好4词可保留。

已保存书籍仍读取articles.sentences，不自动重分或迁移。本书16组合并、5组纠正稿及原5个保留短槽都是历史数据事实；它们不会因新算法试验被直接写回。

## 2. 原有长度层级必须完整保留

不得把最终允许范围简单写成“4–30词都可以”。按统一规范§1、§8.1、§9执行：

1. **合适范围**：正常目标8–16词；不满8词仍要按功能块/碎片规则判断。<=16不因长度主动再切，不等于任何4–7词碎片都合格。
2. **弹性与逐步加强**：17词处于弹性区；无标点17–20词可在低风险舒适句法点切，也可因结构风险KEEP。不能把17词做成新的硬上限。
3. **有标点时加强**：18–20词内部有可用原文标点或delimiter边缘时必须优先在那里切；不得因总词数<=30而直接保留。
4. **强制分句**：21–30词无论有无标点都必须继续求解，标点优先；没有可用标点时才找安全句法边界。原文没有合法边界时记录真实不可行原因，不宣称长块合格。
5. **绝对硬上限**：最终任一块不得>30词。必要的emergency继续按原规则可观察处理，不能用它放行任意长块，也不能违反最小词数和原文保真。

“可用切点”须同时满足新的最终最小词数及原硬保护；把18词切回16+2并不合格。同一DAG求合法完整路径，不先接受短尾再补救。AI只能选这些完整合法路径，不能生成任意文本或新增边界。

## 4. 最小代码修改面：复用并替换

### 4.1 首次求解前合并单元

`read_aloud_splitter_v3_solver.dart` 的plan目前先处理parser区间与delimiter，再遍历单元调用_buildSentenceFacts和_AdditiveReadAloudLatticeV3.solve。短单元整理必须在该循环之前完成。

整理时使用生产词数，合并不足4词的原单元及必要邻单元；延续原短引语优先向后、其余先向前再向后的方向原则，受原硬保护约束。相邻短链须先形成完整待求解单元再构建事实，不能1+1后把2词单元送入求解。无目标输入尽量直接复用原单元。

保持范围由目标短链和必要邻接内容触发，不把普通整章无条件拼成一个巨大单元。合并完成后才调用词法/句法完整事实构建，避免边试合并边调用DAG。词数/词位等已计算事实要复用，避免每次累加单元都重复扫描累计全文或反复复制整个token前缀。

### 4.2 同一DAG内保证终态
